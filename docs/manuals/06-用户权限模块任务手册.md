# 用户权限模块任务手册

## 已验证能力

系统使用 BCrypt 密码哈希、JWT 认证、五类初始化角色与后端 `@PreAuthorize` 权限检查。`POST /api/auth/login` 成功登录、JWT 往返及业务接口 401/403 在 2026-10-15 历史测试基线中已验证。登录页已实现，用户/角色维护 API 和页面尚未实现。

## 失败计数与锁定

`sys_user.failed_attempts`、`locked_until` 保存锁定状态，既有设计为连续失败 5 次锁定 15 分钟；到期后自动允许再次登录，成功登录重置失败次数。系统没有管理员手工解锁 API，不应将到期自动解锁描述为手工解锁。

历史版本的 `AuthController.login` 在同一事务中增加失败次数、写入 `sys_audit_log` 后抛未检查异常。2026-10-14 的 PostgreSQL 专项检查显示错误密码返回 400，失败次数和失败审计均未提交，故**历史基线的失败锁定与失败审计未验收**。

2026-10-30 状态：`LoginStateService` 以独立短事务和用户行锁更新状态、写审计；`InvalidCredentialsException` 统一返回 401。`AuthPostgresIntegrationTest` 4/4 已在真实 PostgreSQL 通过，覆盖失败计数、第五次锁定、到期解锁、成功重置、未知账号统一响应和并发计数；这是当前验收结果，不改变上段历史失败事实。审计写入失败会导致状态事务失败，不得视为审计成功。测试基础设施曾因 Docker API 协商和 Ryuk 镜像阻塞，处理见 `docs/optimization/kyc-closure-report.md`。

## 源码、数据与验收

认证入口见 `backend/src/main/java/com/example/aml/auth/`，过滤器和权限配置见 `security/`，实体与仓库见 `user/`，审计写入见 `audit/AuditService.java`。数据表为 `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`sys_audit_log`。`JwtServiceTest`、`CoreWorkflowIntegrationTest` 和 `AuthPostgresIntegrationTest` 分别支撑令牌、成功路径与失败提交的验收结论。

用户/角色 CRUD、管理员手工解锁、密码重置、刷新令牌与 MFA 未实现。演示账号仅限本地开发，不应在文档、日志或截图中记录真实密码和令牌。
