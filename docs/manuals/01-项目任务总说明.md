# Java AML 项目任务手册

## 1. 项目边界

本项目是可独立运行的反洗钱教学与演示平台，不是生产合规结论系统。只允许使用合成、脱敏或公开许可数据；模拟名单结果必须标记为 `SIMULATED`，真实外部适配结果标记为 `REAL`。规则阈值、风险分数和命中只表示调查线索，不构成违法认定，不自动提交监管报告。

技术基线为 Java 21、Spring Boot 3.5.7、Drools 10.1.0、PostgreSQL 16、Flyway、Vue 3、TypeScript、Vite、Element Plus、ECharts、Docker Compose。

## 3. 标准开发任务流

1. 阅读 `AGENTS.md`、`docs/PROJECT_PLAN.md`、`docs/PROGRESS.md`，确认数据和外部系统边界。
2. 数据结构只通过 `backend/src/main/resources/db/migration/Vn__*.sql` 前向演进；不得修改已发布迁移，也不得依赖 Hibernate 自动建表。
3. 后端按领域目录增加 Entity/Repository、DTO、Service、Controller；写操作增加 Bean Validation、事务、权限和审计。
4. 外部系统通过接口和适配器隔离，配置超时；禁用、超时、非 2xx 和坏响应必须明确失败，不能用模拟结果冒充真实成功。
5. 前端增加 API 调用和页面状态，至少覆盖加载、空数据、错误、无权限；统计值只能来自后端数据库查询。
6. 增加单元或集成测试，然后依次执行后端测试、前端构建、空库迁移和 HTTP E2E。
7. 更新 API、数据库、部署、测试结果和进度文档；未实连的外部系统明确记为未验证。

## 4. 验收清单

在仓库根目录执行：

```powershell
docker compose config --quiet
docker compose --progress plain build backend
Set-Location frontend
npm ci
npm run build
npm audit --omit=dev --registry=https://registry.npmjs.org
Set-Location ..
docker compose --profile app up -d --build
Invoke-RestMethod http://localhost:8080/actuator/health
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\e2e-smoke.ps1
```

本机必须使用 JDK 21。若系统 `java -version` 仍为 Java 8，可直接使用 Docker 构建；不要把 Java 8 下测试进程启动失败记录为代码测试失败。

验收通过要求：后端测试零失败；Vue 类型检查和 Vite 构建成功；Flyway 在全新 PostgreSQL 数据库从 V1 到 V6 全部成功且 Hibernate `validate` 通过；健康为 `UP`；E2E 输出 `result=PASS`、案件为 `CLOSED`、二次规则执行 `duplicateRuleHits=0`。

## 5. 日常操作

- 登录后从“客户管理”创建合成客户，再开户并通过“交易管理”导入合成流水。
- 在“规则管理”执行已实现规则；R004–R008 为规划项，数据库中保持禁用。
- 在“预警管理”人工复核并升级案件；案件依次经过调查、待复核和关闭。
- 名单筛查默认使用 Mock，页面和数据均显示模拟来源；只有配置并启用 Yente 后才可选择真实 Provider。
- 仪表盘和 CSV 使用实时 SQL；审计导出最多 10000 行。
- E2E 脚本会写入带 `E2E-` 前缀的合成业务记录，以便保留审计证据；它只删除自己的临时 CSV 文件。
