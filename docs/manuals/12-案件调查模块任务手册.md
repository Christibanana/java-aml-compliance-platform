# 案件调查模块任务手册

## 1. 模块目标

将规则预警升级为可分派、可调查、可复核、可关闭且全程可审计的案件。

## 2. 已实现业务流程

1. `IN_REVIEW` 预警事务性升级为案件，预警变为 `ESCALATED`。
2. 案件分派给启用且拥有 `CASE_INVESTIGATE` 权限的调查员。
3. 调查员添加调查笔记并上传证据；证据可下载或填写原因后逻辑移除。
4. 状态按 `OPEN → INVESTIGATING → PENDING_REVIEW → CLOSED` 流转；复核可退回调查。
5. 关闭时保存调查结论；关闭后所有案件写操作均被拒绝。

## 3. 数据库与存储

- 核心表：`aml_case`、`aml_case_alert`、`aml_case_note`、`aml_case_evidence`、`aml_case_history`。
- Flyway V5 增加证据活动标记、移除时间/人员/原因、完整性约束及案件查询索引。
- 证据保存到配置项 `aml.evidence.storage-root`；Compose 使用 `aml-evidence` volume。
- 允许 PDF、PNG、JPEG、TXT、CSV，最大 10MB；保存 SHA-256。逻辑移除不会删除底层文件。

## 4. 后端接口

- `GET /api/cases`：按状态、优先级、调查员和关键词分页查询。
- `GET /api/cases/{id}`：查询预警、笔记、活动证据和状态历史聚合详情。
- `GET /api/cases/investigators`：查询可分派调查员。
- `POST /api/cases/{id}/assign|notes|transition`：分派、笔记和状态流转。
- `POST /api/cases/{id}/evidence`：multipart 上传证据。
- `GET /api/cases/{caseId}/evidence/{evidenceId}/download`：下载并审计。
- `DELETE /api/cases/{caseId}/evidence/{evidenceId}`：带原因逻辑移除。

全部接口要求 `CASE_INVESTIGATE` 权限。分派、笔记、状态和证据操作均写 `sys_audit_log`。

## 5. 前端工作台

`CasesView.vue` 提供案件筛选与分页、聚合详情抽屉、调查员分派、状态操作、笔记编辑、证据上传/下载/移除，以及关联预警和状态历史时间线。

## 6. 状态约束

- 未分派案件不能从 `OPEN` 进入 `INVESTIGATING`。
- 没有调查笔记不能提交 `PENDING_REVIEW`。
- 只有 `PENDING_REVIEW` 可关闭；关闭结论不能为空。
- `CLOSED` 为终态，不能重开或修改笔记/证据/分派。

## 7. 测试与验收

- `CaseServiceTest`：非法重开、未分派开始调查、无笔记提交复核。
- `CaseEvidenceServiceTest`：上传、SHA-256、路径与类型校验。
- `CoreWorkflowIntegrationTest`：交易→规则→预警→升级案件→分派→笔记→证据→复核→关闭，并验证关闭后写入被拒绝。
- 真实 PostgreSQL/Flyway/HTTP 验收结果见 `docs/deployment/phase3c-case-validation-2026-10-14.md`。

## 8. 后续扩展

多预警手工并案、复核人与调查员职责分离、病毒扫描端口、S3/MinIO 对象存储、证据保留策略与法律保全标记。本阶段未实现这些扩展项。
