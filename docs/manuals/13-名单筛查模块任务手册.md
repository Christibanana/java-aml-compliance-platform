# 名单筛查模块任务手册

## 1. 模块目标
以可替换 Provider 返回需人工复核的候选匹配。
## 2. 业务背景
名称相似不等于身份一致，更不等于违法。
## 3. 功能需求
请求、候选、详情、人工复核和结论。
## 4. 业务流程
输入名称→Provider 搜索→保存请求/候选→人工复核。
## 5. 数据库设计
`aml_screening_request/match/review`。
## 6. 后端实现方案
`ScreeningProvider` 端口，提供 Yente HTTP 与显式模拟两种适配器；Registry 负责选择、可用性和数据模式校验。
## 7. 前端页面设计
筛查表单、Provider 状态、真实/模拟警告、候选表格、历史详情和人工复核已实现。
## 8. API 接口说明
`GET/POST /api/screenings`、`GET /api/screenings/providers`、`GET /api/screenings/{id}`、`POST /api/screenings/{requestId}/matches/{matchId}/review`。
## 9. 关键源码路径
`backend/.../screening`、`ScreeningView.vue`。
## 10. 权限要求
要求 `SCREENING_EXECUTE`。
## 11. 异常处理
Yente 有连接/请求超时、HTTP 状态和响应格式检查。失败请求持久化为 `FAILED` 并写审计，API 返回 502；禁止静默返回空集合或改用 Mock。
## 12. 测试用例
Mock 确定性结果、Yente 请求/鉴权/响应契约、503、禁用状态、失败落库、人工复核及完整业务闭环已通过。
## 13. 验收标准
模拟结果醒目标识，任何候选不得自动定案。
## 14. 已实现功能
Provider 接口、Yente 与 Mock 适配器、来源标记、请求/候选保存查询、人工复核、失败审计和 Vue 页面。
## 15. 未实现功能
真实外部 Yente 实例尚未在本机配置或实连；适配器由本地 HTTP stub 完成契约测试。
## 16. 后续扩展建议
核验 Yente 目标版本契约并加入契约测试和熔断。
