# 系统部署操作手册

## 1. 适用范围

仓库内 Compose 是单机开发/演示部署，不是生产高可用方案。默认启动 PostgreSQL；带 `app` profile 才启动后端和前端。所有默认口令仅供本机演示，禁止用于共享或生产环境。

## 2. 前置条件

- Docker Engine 29.x 或兼容版本、Docker Compose v2/v5。
- 如需宿主机开发：JDK 21、Maven 3.9、Node.js 24、npm 11。
- 默认空闲端口：5432、8080、5173；可通过环境变量改写。
- Windows PowerShell 5.1 可运行 E2E 脚本；脚本内容保持 ASCII 以避免旧版 PowerShell 的 UTF-8 无 BOM 解析问题。

检查命令：

```powershell
docker version
docker compose version
java -version
mvn -version
node --version
npm --version
docker compose config --quiet
```

本项目要求 Java 21。本机如果只有 Java 8，请使用容器构建；后端 Dockerfile 的构建和运行阶段均固定 Eclipse Temurin 21。

## 3. 配置

复制 `.env.example` 为 `.env`，至少修改：

| 变量 | 用途 | 要求 |
|---|---|---|
| `AML_DB_NAME/USER/PASSWORD` | PostgreSQL 库和账号 | 生产使用独立强密码与密钥注入 |
| `AML_JWT_SECRET` | JWT HMAC 密钥 | 至少 32 字节，禁止提交仓库 |
| `AML_DEMO_USERNAME/PASSWORD` | dev profile 演示管理员 | 仅 dev 使用，部署后立即更换 |
| `AML_*_HOST_PORT` | 三服务宿主端口 | 端口冲突时改写 |
| `AML_EVIDENCE_STORAGE_ROOT` | 证据目录 | Compose 内固定 `/app/data/evidence` 并挂卷 |
| `AML_YENTE_*` | Yente 地址、数据集、密钥、阈值、超时 | 未实连时保持 `ENABLED=false` |
| `AML_FINERACT_*` | Fineract 地址、租户、账号、超时 | 未实连时保持 `ENABLED=false` |

外部适配器禁用时本地客户、交易、规则、案件、Mock 筛查和报表仍可独立运行。不能把 Mock 配置成真实数据，也不能在真实 Provider 失败时静默切换 Mock。

## 4. 构建和启动

```powershell
# 配置语法
docker compose config --quiet

# 先在可访问 Docker 的宿主机运行完整后端测试
cd backend
mvn -B test
cd ..

# 镜像构建；后端镜像仅编译打包，避免在构建容器内运行 Testcontainers
docker compose --progress plain --profile app build backend frontend

# 启动数据库、后端和前端
docker compose --profile app up -d
docker compose --profile app ps
```

访问地址：前端 `http://localhost:5173`，后端健康 `http://localhost:8080/actuator/health`，OpenAPI `http://localhost:8080/v3/api-docs`，Swagger UI `http://localhost:8080/swagger-ui.html`。

首次启动顺序为 PostgreSQL 健康后启动后端；Flyway 自动迁移，随后 Hibernate 只做结构校验。不要设置 `ddl-auto=create/update`。

## 5. 验收

```powershell
$health = Invoke-RestMethod http://localhost:8080/actuator/health
$health.status
(Invoke-WebRequest -UseBasicParsing http://localhost:5173/).StatusCode
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\e2e-smoke.ps1
```

E2E 使用 `E2E-*` 合成记录，验证 JWT、RBAC、客户、账户、交易、导入幂等、Mock 筛查、人工复核、R001、规则幂等、两类评分、预警、案件、证据、统计、审计和 CSV。输出必须包含 `result: PASS`、`caseStatus: CLOSED`、`firstRuleHits: 1`、`duplicateRuleHits: 0`。

数据库迁移核对：

```powershell
docker compose exec -T postgres psql -U aml -d aml -c `
  'select installed_rank,version,description,success from flyway_schema_history order by installed_rank'
```

## 6. 数据和备份

`aml-postgres` 保存数据库，`aml-evidence` 保存证据物理文件。普通 `docker compose down` 不删除卷；`down -v` 会删除数据库和证据，除非用户明确要求清空，否则禁止执行。

示例备份：

```powershell
docker compose exec -T postgres pg_dump -U aml -d aml -Fc > aml-backup.dump
```

恢复必须在新库演练，随后校验 Flyway 历史、34 张应用表、关键业务行数以及证据卷的一致性。数据库备份不包含证据文件，证据卷必须单独备份并核对 SHA-256。

## 7. 日志和故障排查

```powershell
docker compose logs --tail=200 backend
docker compose logs --tail=100 postgres
docker compose exec -T postgres pg_isready -U aml -d aml
docker compose ps
```

- 后端提示 class file 61/65 不兼容：实际使用了 Java 8；改用 JDK 21 或容器构建。
- Flyway 校验和错误：不要修改旧迁移，恢复原文件并新增下一版本。
- 端口占用：设置 `AML_POSTGRES_HOST_PORT`、`AML_BACKEND_HOST_PORT`、`AML_FRONTEND_HOST_PORT`。
- Yente/Fineract 返回 502：检查是否显式启用、URL、租户/密钥、超时和外部服务；本地核心功能无需依赖它们。
- npm audit 在镜像站返回 404：使用 `npm audit --registry=https://registry.npmjs.org`，不要把镜像能力缺失当成零漏洞。
- 前端能打开但 API 失败：检查 Nginx `/api` 和 `/actuator` 代理以及后端容器日志。

## 8. 停止与升级

```powershell
docker compose --profile app stop
docker compose --profile app start
docker compose --progress plain --profile app up -d --build
```

升级前备份数据库与证据；评审新增 Flyway；在空库和备份副本分别演练；执行自动化测试与 E2E；确认健康与审计后再切换。回滚应用镜像不能自动回滚数据库结构，应为迁移设计向前兼容策略。

## 9. 生产化缺口

上线前还必须完成 TLS/WAF、反向代理安全头、外部密钥管理、数据库最小权限、备份恢复演练、集中日志和指标告警、恶意文件扫描、对象存储、漏洞/SBOM 扫描、CI/CD、滚动发布、容灾和监管数据治理。`dev` profile 及演示管理员初始化必须关闭。
