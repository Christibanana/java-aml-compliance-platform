# 规则引擎模块任务手册

## 1. 模块目标
版本化、可解释、幂等地检测 AML 教学规则。
## 2. 业务背景
规则参数需治理，执行结果需可追溯。
## 3. 功能需求
配置、版本、启停、执行、命中、测试和批量检测。
## 4. 业务流程
读取启用版本→解析受控参数→扫描事实→生成唯一命中→生成预警。
## 5. 数据库设计
`aml_rule/_version/_execution/_hit`。
## 6. 后端实现方案
当前 R001 用受控 Java 执行器；禁止用户任意 DRL。
## 7. 前端页面设计
规则列表、参数展示和批量执行已实现。
## 8. API 接口说明
`GET /api/rules`、`POST /api/rules/execute`、执行记录查询。
## 9. 关键源码路径
`backend/.../rule/RuleExecutionService.java`。
## 10. 权限要求
执行要求 `RULE_EXECUTE`。
## 11. 异常处理
参数 JSON 错误终止执行；唯一 `hit_key` 防重。
## 12. 测试用例
编译通过；R001 PostgreSQL 数据集成与重复执行测试待补。
## 13. 验收标准
阈值版本明确、解释可读、重复运行不重复预警。
## 14. 已实现功能
八条规则元数据/版本、R001 执行/命中/预警。
## 15. 未实现功能
R002～R008 算法、启停/新版本 API、Drools 模板执行。
## 16. 后续扩展建议
先实现窗口聚合索引，再实现图路径规则并做规模基准。
