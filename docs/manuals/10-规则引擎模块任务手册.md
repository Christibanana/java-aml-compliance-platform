# 规则引擎模块任务手册

## 范围与流程

当前仅 AML-R001 单笔大额、R002 短时高频、R003 窗口累计金额具有可执行算法。`RuleConfigService` 管理版本、参数和启停；`RuleExecutionService` 查询交易并构造 `RuleEvaluationFact`，其中 R002/R003 按账户和客户在配置时间窗口内聚合；`DroolsRuleEvaluator` 编译 `rules/transaction-monitoring.drl`，调用 KIE session 的 `fireAllRules()`，命中后生成预警。

用户只能提交白名单参数，不可提交或执行任意 DRL。阈值仅为教学配置。当前由用户触发批量执行，没有流式调度器。执行开始后的业务异常由独立事务保留 FAILED；参数预检或执行记录插入前失败不产生记录。2026-10-23 的默认联合执行曾因 `scope varchar(30)` 插入失败，Flyway V7 已扩大为 `varchar(160)` 并在真实 PostgreSQL 验证。

## API 与权限

基础路径 `/api/rules`：`GET /`、`GET /{code}/versions`、`POST /{code}/versions`、`PUT /{code}/status`、`POST /execute`、`GET /executions`、`GET /hits`、`GET /compatibility`。规则读取要求 `CUSTOMER_READ`，执行、版本创建、启停与执行记录读取要求 `RULE_EXECUTE`。预警查询、分派和审核使用 `/api/alerts` 与 `ALERT_REVIEW`；升级案件要求 `CASE_INVESTIGATE`。

## 数据库与幂等

Flyway V1/V3/V4 定义规则并禁用规划项，V7 扩大执行范围字段。数据位于 `aml_rule`、`aml_rule_version`、`aml_rule_execution`、`aml_rule_hit`、`aml_rule_hit_transaction`、`aml_alert`、`aml_alert_transaction` 和 `aml_alert_history`。唯一 `hit_key` 与预警关联约束防止相同命中重复生成；并发场景尚无完整专项验收。

## 测试与边界

`DroolsRuleEvaluatorTest` 验证三条 DRL 的阈值命中和未命中；`RuleParameterValidatorTest` 验证参数；`KycAndRulePostgresIntegrationTest` 在 Flyway V1–V7 PostgreSQL 上执行默认三规则并验证 R001 命中与二次幂等；2026-10-30 的 Edge 测试也直接点击默认按钮，不停用 R002/R003。R002/R003 的时间窗口边界由 `RuleExecutionReliabilityTest` 与历史记录覆盖；单条模拟交易只命中 R001，不等于另两条规则没有执行。

截至 2026-10-15 的历史基线，R001–R003、版本管理、启停 API 和 Drools 执行已验证。R004–R008 仅有元数据和初始参数，数据库状态为 `PLANNED/disabled`，执行器明确拒绝；图路径、行为基线、审批发布和实时调度未实现。
