# 风险评分模块任务手册

## 1. 模块目标
生成可解释、可追溯的客户和交易风险分数。
## 2. 业务背景
评分用于优先级排序，不能替代人工结论。
## 3. 功能需求
客户/交易评分、规则加权、等级映射、解释与历史。
## 4. 业务流程
收集特征→按版本权重计算→映射等级→保存解释历史。
## 5. 数据库设计
客户与交易均有当前风险和只追加历史表，保存来源、模型版本、解释、计算人和时间。
## 6. 后端实现方案
已实现确定性规则评分：客户综合基础风险、资料完整度、预警、筛查复核和交易量；交易综合金额、对手方完整度、规则命中和客户风险。
## 7. 前端页面设计
独立风险评分页已实现，可按客户/交易 UUID 重算、查看当前结果和历史。
## 8. API 接口说明
`/api/risk-scores/customers/{id}` 与 `/transactions/{id}` 提供重算、当前结果和历史接口。
## 9. 关键源码路径
`backend/.../risk/RiskScoringService.java`、`RiskScoringController.java`、`frontend/src/views/RiskScoresView.vue`。
## 10. 权限要求
计划读取 `REPORT_READ`，重算由经理权限控制。
## 11. 异常处理
缺失资料作为明确因素进入解释；评分保存 `NONE/REAL/SIMULATED/MIXED`，模拟筛查权重低于真实筛查且页面持续警示。
## 12. 测试用例
核心 HTTP 集成测试覆盖客户和交易各两次计算、历史追加、模型版本与模拟来源传播；PostgreSQL 运行态复验通过。
## 13. 验收标准
同版本输入可复现，结果含因素、权重和版本。
## 14. 已实现功能
客户/交易评分、等级映射、因素解释、当前快照、只追加历史、来源传播、权限、审计和 Vue 页面。
## 15. 未实现功能
模型参数管理和人工覆盖尚未实现；当前为固定版本的教学规则模型。
## 16. 后续扩展建议
先实现规则型评分，再评估模型服务并保留人工覆盖审计。
