# 技术决策记录

## ADR-001：模块化单体

- 状态：采用
- 决策：单个 Spring Boot 部署单元，按 `auth/customer/account/transaction/rule/alert/casework/...` 划分包。
- 理由：最小闭环事务一致性清晰、部署简单，同时保留未来拆分边界。

## ADR-002：Java 与依赖基线

- 状态：采用，构建待本机 Java 21 验证
- 决策：Java 21、Spring Boot 3.5.x、springdoc 2.8.x、Drools 10.1.x、PostgreSQL 16。
- 理由：Java 21 为 LTS；Spring Boot 3.5 仍处于成熟 3.x 生态；Drools 10 系列已明确加入 Java 21 支持。精确补丁版本在 `pom.xml` 锁定。
- 限制：当前机器只有 Java 8，首次后端构建结果必须保持“未执行成功”。

## ADR-003：受控规则而非任意 DRL

- 状态：采用
- 决策：规则版本只保存受控类型和 JSON 参数；DRL 由应用内模板生成/加载，业务用户不能提交可执行代码。
- 理由：避免代码注入并支持阈值版本化与审计。

## ADR-004：外部筛查降级

- 状态：采用
- 决策：`ScreeningProvider` 为端口；Yente 为可选真实数据适配器，本地默认使用明确标记为模拟数据的 Provider。用户明确选择 Yente 后，任何超时、网络、HTTP 或响应格式错误都记录失败并返回 502，禁止静默切换到 Mock。
- 理由：本地演示可独立运行，同时防止外部故障被误解为“未命中”或把模拟命中伪装成真实制裁结论。

## ADR-005：确定性风险评分及数据来源传播

- 状态：采用
- 决策：第一版使用可解释的规则加权模型，客户与交易分别固定模型版本；每次计算更新当前快照并追加历史。交易评分继承关联客户的来源，真实和模拟因素并存时标为 `MIXED`。
- 理由：教学平台需要结果可复现、可审计，并让使用者能够判断分数是否受到模拟名单数据影响。评分用于排序，不构成监管或法律结论。
