# 系统需求规格说明书

## 目标与边界

平台支持合成客户和交易的合规演示闭环：客户→账户→交易导入→规则检测→预警审核→案件调查。系统不连接生产金融系统，不自动提交监管报告，不把名单候选视为违法结论。

## 角色

- `SYSTEM_ADMIN`：用户、角色和全部业务管理。
- `AML_ANALYST`：客户/账户/交易、规则执行和预警审核。
- `AML_INVESTIGATOR`：案件调查与筛查复核。
- `AML_MANAGER`：规则、预警、案件、报表与审计管理。
- `AML_AUDITOR`：只读报表和审计。

## 核心验收流

1. 授权用户登录并获得有时效的 JWT。
2. 创建合成客户与账户。
3. 导入格式正确的合成 CSV；拒绝无效行且跳过重复流水。
4. 执行 AML-R001，对达到版本化阈值的交易创建唯一命中和预警。
5. 审核预警并升级案件；非法状态转换被拒绝。
6. 保存调查笔记，提交复核并关闭案件；关键操作可审计。

## 非功能要求

- 金额为精确十进制，时间为 UTC；所有写接口校验输入。
- 默认拒绝未认证访问，权限由后端执行。
- 外部服务超时或不可用不能阻断核心闭环。
- 日志和演示数据不得包含真实身份信息或密钥。
